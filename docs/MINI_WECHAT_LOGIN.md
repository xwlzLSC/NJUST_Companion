# 小程序智慧理工微信授权

新增入口：小程序“设置 → 微信授权登录”。保留智慧理工账号/密码登录，并提供：

- 二维码登录：用学校返回的短时授权链接在本机画布生成二维码，另一台设备扫码；同一手机可保存到相册，再使用微信“扫一扫 → 相册”识别。
- 链接登录：复制学校授权链接，在自己的微信聊天中打开并确认，返回小程序设置页。

两种方式共用同一个学校授权 UUID；切换方式不刷新授权。返回设置页自动检查，也可点击“我已确认，检查登录”。学校授权短时有效，页面显示倒计时，过期后需手动重新获取。

这不是用 `wx.login` 自动登录学校：学校账号需绑定授权所用的微信。小程序没有学校微信应用的身份，不能替用户确认学校授权，也不提供虚构的“直接授权”跳转。

## 2026-10-01：旧客户端的图片文件兼容（现为备用路径）

以下写入 / 解码策略仅在客户端没有画布 API 时使用，不再是新版小程序的二维码显示主路径。

本次只修改实际小程序项目的 `miniprogram/utils/wechat-login.js`、`pages/profile/index.wxml` 和 `index.wxss`。云端授权协议 / `wechatRevision` 不变；已有微信登录云函数无需重新上传。请在 `E:\NJUST_companion` 项目清除**编译缓存**后重新编译 / 预览，再点击「重新获取」或「重新加载二维码」。不要为此清除账号、课表等本地数据。

- 学校图片 Base64 在本机转换成二进制以校验图片签名。保存时优先使用 `writeFile({ data: 纯Base64内容, encoding: 'base64' })`，不传 Data URI 前缀；对于旧客户端再尝试 `ArrayBuffer` 写入，不依赖已废弃的 `wx.base64ToArrayBuffer`。两个策略使用不同文件名，避免迟到回调删除成功的图片。
- 本地文件写入之后通过 `wx.getImageInfo` 检查图片是否能解码，再绑定到 `<image>`，不再把「文件写入成功」当作「图片一定可显示」。写入 / 解码各有 6 秒等待上限，失败保留可用的链接方式并显示原因。
- 复用仍可解码的已有图片；损坏 / 丢失的文件自动重建。图片组件有 `bindload` / `binderror`，显示失败时自动重建一次，此后保留明确错误和「重新加载二维码」。每次重建使用新的文件名，避免继续命中失败图片缓存。
- 图片重试不重新申请学校授权，二维码和链接仍共用同一次挑战。重复点按合并写入；过期 / 取消后迟到回调不会显示旧图，只清理本功能自己生成的文件，不删除其它用户文件。
- 写入回调超时后立即释放等待状态，不再进入另一轮等待；存储空间 / 文件权限错误不会盲目重复写入，并显示分类原因而非包含私有授权编号的原始路径。

Base64 / 二进制写入和本地解码检查参照 [微信官方 API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts) 中 `WriteFileOption`、`GetImageInfoOption` 的接口约定。

验证：`npm run test:mini-wechat` 共 32 项通过，新测试实际解码 PNG 字节，不再使用只有文件写入成功的模拟。覆盖纯 Base64 编码、二进制兼容回退、编码被忽略时的解码修复、空间不足、开发者工具路径、损坏缓存、原生图片失败、写入 / 解码失败、超时、取消和迟到回调。`node scripts/probe-mini-wechat-cloud.cjs` 匿名验证实际云函数取得 400×400 学校二维码，再经过实际小程序的转换 / 校验代码；输出字节与学校响应一致且可解码。数据库、客户端存储及文件全部在内存模拟，不登录真实账号、不部署、不保存或输出授权码 / Cookie。真实 `<image>` 组件、微信授权和相册权限仍需手机验证。
