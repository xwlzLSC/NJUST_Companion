# 课表检查、变更与考试提醒

本次新增四项覆盖网页、Android APK 和微信小程序。入口在设置页；课表工具中也有“完整性检查 / 变更记录”。小程序考试页可进入“考试提醒 / 提醒检查”。

## 课表完整性检查与变更

- 自动检查星期、节次、周次和地点，保留 `weekText` 原始周次以核对 `4-5,8-12(周)` 等分段安排。
- 同一账号、同一学期，有上次课表时，本次异常或意外空结果不会覆盖上次有效课表。失败或未同步的模块不参与变更比较。
- 首次同步只建立基线；以后合并等价的分段周次后比较新增、删除及时间/地点/周次/教师变化，保留最近 10 次变更。
- 可以恢复某次同步之前的本地课表；不修改学校数据、成绩、考试、自定义课程。下次新同步仍以学校数据为准。
- 检查只能检查实际抓到的数据，不能保证网页上未抓到的课程不存在。旧缓存若缺少原始周次，请重新同步以获得完整检查依据。

## Android 与网页

在设置中启用“消息通知”和“考试提醒”，安排考前一天、考前两小时的系统本地提醒。日期/时间不明确、已过期、提醒时刻已过时不安排。所有课程、待办和考试按提醒时间排序，最多排队 64 条。同步或设置变化后重新安排；系统通知与精确闹钟权限、手机后台省电限制仍影响送达。

“提醒检查”展示候选计划与系统 `getPending()` 队列分别核对，可重新安排、发出 5 秒后的测试通知。网页只有预览，不宣称支持后台系统通知。

## 微信小程序部署

实际小程序项目：`E:\NJUST_companion`。本仓库内 `integrations/wechat/cloud` 保存新增云端逻辑源文件；部署项目内的 `lib` 副本须保持一致。纯检查逻辑 `js/schedule-insights.js` 与小程序 `utils/schedule-insights.js` 相同。

本次覆盖前的原文件备份在 `F:\NJUSTKB\output\four-features\before-install`，没有删除原项目目录。

1. 在微信开发者工具中选择正确云环境，上传并部署 **njustSync2**、**todoReminderTimer**，选择“云端安装依赖”。只编译小程序不会更新云端。
2. 为 `todoReminderTimer` 配置定时触发器，建议每分钟运行，Cron：`0 * * * * * *`。配置文件已附带该触发器。旧的 `njustSync2` 定时触发器也接入同一发送器，有数据库发送锁以防两个触发器重复发送。
3. 保持当前已配置的“工作任务待办通知”订阅模板。考试以“考试安排”任务发送，与待办共享此模板的订阅额度。每条考试提醒需要单独点击授权；两次提前提醒需要分别授权，不能一次授权承诺无限推送。
4. 新集合 `njust_exam_reminders`、`njust_reminder_health` 由云函数自动建立。建议客户端数据库权限设置为不可直接读写；所有访问通过云函数，根据调用者 OPENID 隔离。
5. 部署后在提醒检查页查看定时器最后扫描时间、云端排队、已发送/失败记录，并发送一条测试订阅消息。测试也会申请并消耗独立订阅额度。

校历时间与云端消息时间按中国时区处理。考试改时间/地点后取消旧的已授权提醒，不静默授权新提醒；用户需重新订阅。定时器停机后超过 1 小时或考试已开始的旧考试提醒会过期，不集中补发。

失败订阅不会无限重试；额度不足/拒绝或模板错误停止发送，网络问题最多重试 5 次。例行同步不会清除发送失败或已发送状态。若需重新授权失败的未来提醒，先取消对应计划，再点击订阅。

## 测试

`npm run test:study`：纯检查与变更、日期时区、提醒排序、云端 OPENID 隔离、发送锁、失败重试、过期处理及小程序存储适配测试。小程序本地测试可设 `MINI_PROGRAM_ROOT` 指向实际 `miniprogram` 目录；不存在小程序源码时只跳过该集成测试。

真实手机后台送达及实际微信订阅额度需要安装或部署后实机验证；本地模拟测试不能替代这两项。
